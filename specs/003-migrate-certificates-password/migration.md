## Overview

This plan defines a one-time, idempotent data migration script that reads all `CourseCompletion` documents from the legacy MongoDB database and inserts them into the V2 PostgreSQL `courses.course_completions` table.

The script is **not** a Next.js API route. It is a standalone Node.js TypeScript script executed once from the developer's machine (or CI) against the target database, **before** the certificates feature is deployed.

---

## The Core ID Mapping Problem

This is the most critical part of the migration. MongoDB and PostgreSQL use completely different ID systems:

| Entity | MongoDB ID | PostgreSQL ID |
|---|---|---|
| User | `ObjectId` (24-char hex) | `text` UUID — assigned by `better-auth` |
| Course | `ObjectId` (24-char hex) | `uuid` — assigned when course was migrated |
| CourseCompletion | `ObjectId` (24-char hex) | `uuid` — new, generated by migration script |

**The bridge is `email` for users and `title` for courses** — these are the only stable identifiers that exist in both systems.

```
MongoDB CourseCompletion
  └── user  (ObjectId) → User.email → auth.user.id (PostgreSQL)
  └── course (ObjectId) → Course.title → courses.courses.id (PostgreSQL)
```

> **Why title for courses?** Course ObjectIds were not preserved when courses were migrated to Postgres. Title is the only reliable human-readable key. If two courses share a title, the migration script will flag the conflict and skip — requiring manual resolution.

## Field-by-Field Mapping

| MongoDB `CourseCompletion` field | Type | PostgreSQL `course_completions` field | Notes |
|---|---|---|---|
| `_id` | ObjectId | *(discarded)* | New `uuid` generated by `defaultRandom()` |
| `user` | ObjectId ref | `user_id` (text) | Resolved via `User.email → auth.user.id` |
| `course` | ObjectId ref | `course_id` (uuid) | Resolved via `Course.title → courses.courses.id` |
| `completedAt` | Date | `completed_at` (timestamptz) | Direct copy |
| `certificateId` | String or null | `certificate_id` (varchar 60) | See rules below |
| `completionPercentage` | Number | `completion_percentage` (integer) | Direct copy |
| `completedLessons` | Number | `completed_lessons` (integer) | Direct copy |
| `totalLessons` | Number | *(not migrated)* | Not in V2 schema — computed from enrollment data |
| `createdAt`, `updatedAt` | Date | *(not migrated)* | V2 table uses `completed_at` only |

### Certificate ID Rules

The legacy MongoDB model uses the same `CERT-<UUID>` format (generated via `crypto.randomUUID()` in a `pre("save")` hook). This means:

| Legacy `certificateId` value | Action |
|---|---|
| `CERT-<UUID>` (new format) | ✅ Copy as-is — already V2-compatible |
| `CERT-XXXXX-XXXXX` (old legacy format) | 🔄 Regenerate: `CERT-${randomUUID().toUpperCase()}` |
| `null` / not set | 🔄 Generate new: `CERT-${randomUUID().toUpperCase()}` |

## The Migration Script

**File**: `scripts/migrate-completions.ts`

```typescript
/**
 * One-time migration: MongoDB CourseCompletions → PostgreSQL course_completions
 *
 * Run:  npx tsx scripts/migrate-completions.ts
 *
 * Idempotent: safe to re-run. Existing rows (matched by certificateId) are skipped.
 * Dry-run:    set DRY_RUN=true to log what would be inserted without writing.
 */

import { MongoClient, ObjectId } from "mongodb";
import { randomUUID }            from "crypto";
import { eq, inArray }           from "drizzle-orm";
import { db }                    from "@/db";
import {
  dbCourseCompletions,
  dbCourses,
}                                from "@/domain/courses/infrastructure/db/courses-db.schema";
import { user as dbUsers }       from "@/db/schema/auth-schema";

// ─── Config ──────────────────────────────────────────────────────────────────
const MONGODB_URI  = process.env.MONGODB_URI!;
const DRY_RUN      = process.env.DRY_RUN === "true";
const BATCH_SIZE   = 50; // rows per Postgres INSERT batch

// CERT-<UUID> V2 format validator
const V2_CERT_REGEX =
  /^CERT-[0-9A-F]{8}-[0-9A-F]{4}-[0-9A-F]{4}-[0-9A-F]{4}-[0-9A-F]{12}$/i;

function makeCertId(): string {
  return `CERT-${randomUUID().toUpperCase()}`;
}

function normalizeCertId(raw: string | null | undefined): string {
  if (!raw)                      return makeCertId(); // null → generate fresh
  if (V2_CERT_REGEX.test(raw))   return raw.toUpperCase(); // already V2 format
  return makeCertId();                                      // legacy format → regenerate
}

// ─── Step 1: Build lookup maps from PostgreSQL ───────────────────────────────
async function buildPgUserMap(): Promise<Map<string, string>> {
  // email (lowercase) → auth.user.id
  const rows = await db
    .select({ id: dbUsers.id, email: dbUsers.email })
    .from(dbUsers);

  const map = new Map<string, string>();
  for (const row of rows) {
    map.set(row.email.toLowerCase(), row.id);
  }
  console.log(`[MAP] Loaded ${map.size} PostgreSQL users by email`);
  return map;
}

async function buildPgCourseMap(): Promise<Map<string, string>> {
  // title (lowercase) → courses.courses.id (uuid)
  const rows = await db
    .select({ id: dbCourses.id, title: dbCourses.title })
    .from(dbCourses);

  const titleCount = new Map<string, number>();
  for (const row of rows) {
    const key = row.title.toLowerCase().trim();
    titleCount.set(key, (titleCount.get(key) ?? 0) + 1);
  }

  const map = new Map<string, string>();
  for (const row of rows) {
    const key = row.title.toLowerCase().trim();
    if (titleCount.get(key) === 1) {
      map.set(key, row.id);
    } else {
      // Duplicate title — cannot resolve unambiguously; will be skipped with a warning
      console.warn(`[WARN] Duplicate course title in Postgres: "${row.title}" — completions for this course will be skipped`);
    }
  }

  console.log(`[MAP] Loaded ${map.size} PostgreSQL courses by title`);
  return map;
}

async function buildExistingCertIds(): Promise<Set<string>> {
  // Load all certificateIds already in Postgres to skip duplicates (idempotency)
  const rows = await db
    .select({ certId: dbCourseCompletions.certificateId })
    .from(dbCourseCompletions);

  const set = new Set<string>();
  for (const row of rows) {
    if (row.certId) set.add(row.certId.toUpperCase());
  }
  console.log(`[MAP] Found ${set.size} existing certificates in PostgreSQL (will skip)`);
  return set;
}

// ─── Step 2: Fetch all completions from MongoDB ──────────────────────────────
interface MongoCompletion {
  _id: ObjectId;
  user: ObjectId;
  course: ObjectId;
  completedAt: Date;
  completionPercentage: number;
  completedLessons: number;
  totalLessons: number;
  certificateId?: string | null;
}

interface MongoUser {
  _id: ObjectId;
  email: string;
}

interface MongoCourse {
  _id: ObjectId;
  title: string;
}

// ─── Step 3: Main migration ──────────────────────────────────────────────────
async function main() {
  console.log(`\n🚀 Starting migration | DRY_RUN=${DRY_RUN}\n`);

  const mongo = new MongoClient(MONGODB_URI);
  await mongo.connect();
  const mongoDb = mongo.db();

  // Build lookup maps
  const pgUserMap    = await buildPgUserMap();
  const pgCourseMap  = await buildPgCourseMap();
  const existingCerts = await buildExistingCertIds();

  // Fetch all Mongo data in memory (collection is small — < 10k docs expected)
  const mongoUsers   = await mongoDb.collection<MongoUser>("users").find({}, { projection: { _id: 1, email: 1 } }).toArray();
  const mongoCourses = await mongoDb.collection<MongoCourse>("courses").find({}, { projection: { _id: 1, title: 1 } }).toArray();
  const completions  = await mongoDb.collection<MongoCompletion>("coursecompletions").find({}).toArray();

  console.log(`[MONGO] Found ${completions.length} CourseCompletion documents`);

  // Build reverse maps: MongoDB ObjectId string → lookup key
  const mongoUserEmailMap  = new Map<string, string>(); // ObjectId → email
  for (const u of mongoUsers) mongoUserEmailMap.set(u._id.toString(), u.email.toLowerCase());

  const mongoCoursesTitleMap = new Map<string, string>(); // ObjectId → title
  for (const c of mongoCourses) mongoCoursesTitleMap.set(c._id.toString(), c.title.toLowerCase().trim());

  // ─── Process each completion ─────────────────────────────────────────────
  const stats = { total: 0, inserted: 0, skipped: 0, failed: 0 };
  const batch: typeof dbCourseCompletions.$inferInsert[] = [];

  for (const doc of completions) {
    stats.total++;

    // Resolve user email → PG userId
    const email   = mongoUserEmailMap.get(doc.user.toString());
    const pgUserId = email ? pgUserMap.get(email) : undefined;
    if (!pgUserId) {
      console.warn(`[SKIP] Completion ${doc._id}: user ${doc.user} not found in PostgreSQL (email: ${email ?? "not found"})`);
      stats.failed++;
      continue;
    }

    // Resolve course title → PG courseId
    const title    = mongoCoursesTitleMap.get(doc.course.toString());
    const pgCourseId = title ? pgCourseMap.get(title) : undefined;
    if (!pgCourseId) {
      console.warn(`[SKIP] Completion ${doc._id}: course ${doc.course} not found in PostgreSQL (title: ${title ?? "not found"})`);
      stats.failed++;
      continue;
    }

    // Normalize cert ID
    const certId = normalizeCertId(doc.certificateId);

    // Skip if already migrated (idempotency)
    if (existingCerts.has(certId)) {
      stats.skipped++;
      continue;
    }

    batch.push({
      userId: pgUserId,
      courseId: pgCourseId,
      completedAt: doc.completedAt ?? new Date(),
      certificateId: certId,
      completionPercentage: Math.round(doc.completionPercentage ?? 100),
      completedLessons: doc.completedLessons ?? 0,
    });

    // Flush batch
    if (batch.length >= BATCH_SIZE) {
      await flushBatch(batch, stats);
      batch.length = 0;
    }
  }

  // Final flush
  if (batch.length > 0) await flushBatch(batch, stats);

  await mongo.close();

  // ─── Summary ──────────────────────────────────────────────────────────────
  console.log(`
╔══════════════════════════════════╗
║     Migration Complete           ║
╠══════════════════════════════════╣
║ Total documents read : ${String(stats.total).padStart(6)} ║
║ Inserted             : ${String(stats.inserted).padStart(6)} ║
║ Skipped (existing)   : ${String(stats.skipped).padStart(6)} ║
║ Failed (unmapped)    : ${String(stats.failed).padStart(6)} ║
╚══════════════════════════════════╝
  `);

  if (stats.failed > 0) {
    console.error(`❌ ${stats.failed} completions could not be migrated. Review [SKIP] logs above.`);
    process.exit(1);
  }

  console.log("✅ Migration completed successfully.");
}

async function flushBatch(
  batch: typeof dbCourseCompletions.$inferInsert[],
  stats: { inserted: number },
) {
  if (DRY_RUN) {
    console.log(`[DRY] Would insert ${batch.length} rows`);
    stats.inserted += batch.length;
    return;
  }
  await db
    .insert(dbCourseCompletions)
    .values(batch)
    .onConflictDoNothing(); // idempotent — skip if certificateId already exists
  stats.inserted += batch.length;
  console.log(`[INSERT] Inserted batch of ${batch.length} rows`);
}

main().catch((err) => {
  console.error("Fatal error:", err);
  process.exit(1);
});
```

## How to Run

### Step-by-Step Execution Order

```bash
# 1. Make sure the DB schema is up to date
npx drizzle-kit push

# 2. Set env vars for the script
$env:MONGODB_URI  = "mongodb+srv://..."      # PowerShell
$env:POSTGRES_URL = "postgresql://..."

# 3. DRY RUN first — verify counts and mappings without writing anything
$env:DRY_RUN = "true"
npx tsx scripts/migrate-completions.ts

# 4. Review output:
#    [MAP] Loaded X PostgreSQL users by email
#    [MAP] Loaded X PostgreSQL courses by title
#    [DRY] Would insert X rows
#    Any [SKIP] or [WARN] lines indicate unresolvable records

# 5. Fix any [SKIP] records (see Troubleshooting below)

# 6. LIVE RUN — write to database
$env:DRY_RUN = "false"
npx tsx scripts/migrate-completions.ts

# 7. Verify (see SQL checks below)
```

> **Safe to re-run.** The script uses `.onConflictDoNothing()` on the `certificateId` unique constraint. Re-running after a partial failure will skip already-inserted rows and resume from unprocessed ones.

## Post-Migration SQL Verification

Run these queries directly against PostgreSQL after the script completes:

```sql
-- 1. Total rows migrated
SELECT COUNT(*) AS total_completions
FROM courses.course_completions;

-- 2. Verify no NULL certificateIds (every completion must have one)
SELECT COUNT(*) AS missing_cert_ids
FROM courses.course_completions
WHERE certificate_id IS NULL;
-- Expected: 0

-- 3. Verify all completions link to valid users
SELECT COUNT(*) AS orphaned_users
FROM courses.course_completions cc
LEFT JOIN auth."user" u ON u.id = cc.user_id
WHERE u.id IS NULL;
-- Expected: 0

-- 4. Verify all completions link to valid courses
SELECT COUNT(*) AS orphaned_courses
FROM courses.course_completions cc
LEFT JOIN courses.courses c ON c.id = cc.course_id
WHERE c.id IS NULL;
-- Expected: 0

-- 5. Check for duplicate certificateIds (must be 0)
SELECT certificate_id, COUNT(*) AS cnt
FROM courses.course_completions
GROUP BY certificate_id
HAVING COUNT(*) > 1;
-- Expected: 0 rows

-- 6. Sample a few rows to visually sanity-check
SELECT
  cc.certificate_id,
  u.email,
  u.name,
  c.title AS course_title,
  cc.completed_at,
  cc.completion_percentage
FROM courses.course_completions cc
JOIN auth."user"      u ON u.id = cc.user_id
JOIN courses.courses  c ON c.id = cc.course_id
ORDER BY cc.completed_at DESC
LIMIT 10;
```

## Troubleshooting Common [SKIP] Causes

| Error in logs | Cause | Fix |
|---|---|---|
| `user not found in PostgreSQL` | User registered in MongoDB but hasn't re-registered in V2 | Ask user to sign up in V2, then re-run script |
| `course not found in PostgreSQL (title: not found)` | MongoDB course ObjectId not in the title map | Course might be deleted; skip is acceptable |
| `Duplicate course title in Postgres` | Two courses with identical title in Postgres | Rename one course in Postgres admin, then re-run |
| `user_id/course_id FK violation` | Postgres FK not satisfied | Run verification queries 3 & 4 above to identify |

---

## Rollback Procedure

If the migration produces bad data, roll back cleanly:

```sql
-- Wipe all migrated completions and start fresh
TRUNCATE TABLE courses.course_completions RESTART IDENTITY CASCADE;
```

Then fix the root cause and re-run the script from Step 3.
