## 2025-01-20 - [Fix timing attack in internal key validation]
**Vulnerability:** The internal API key check used strict equality (`===`), making it vulnerable to a timing attack where an attacker could theoretically guess the key by measuring the response time.
**Learning:** Even internal validation checks against environment secrets must use constant-time comparison to prevent timing attacks. Additionally, relying on `|| ""` empty string fallbacks for `timingSafeEqual` comparison can inadvertently grant authorization if the environment key is unset and the client sends an empty header string. Using `.length` on strings rather than buffers can throw `RangeError` with multi-byte characters.
**Prevention:** Always compare string values using `crypto.timingSafeEqual` after converting to Buffers. Ensure neither value is null or empty, verify that `providedBuf.length === expectedBuf.length`, and never use `|| ""` empty string fallbacks that could match each other under misconfigured conditions.
