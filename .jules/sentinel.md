## 2024-05-18 - Prevent Timing Attacks in API Key Validation
**Vulnerability:** Comparing API keys using strict equality (`===`) exposes the application to timing attacks, where an attacker can theoretically guess the key by measuring the time the comparison takes.
**Learning:** Strict equality checks fail early. A character-by-character comparison (like `===` often does under the hood for strings) means strings that mismatch at the first character fail faster than strings that mismatch at the last character. Over a network, this difference can sometimes be measured. Furthermore, using strings directly with `timingSafeEqual` can cause `RangeError` if lengths mismatch. Empty strings for both keys can cause an unexpected authentication bypass if the environment variable is not defined.
**Prevention:** Use `crypto.timingSafeEqual` from `node:crypto`. Convert strings to Buffers first (`Buffer.from(key)`). Verify that both keys are defined and not empty, and ensure that their lengths match (`buf1.length === buf2.length`) before calling `timingSafeEqual`, to prevent `RangeError`.
