## 2024-06-12 - [Timing Attack and Auth Bypass via String Comparison]
**Vulnerability:** The internal API endpoint for checking storage used a strict equality comparison (`===`) to compare the user-provided `x-internal-key` against the `INTERNAL_API_KEY` environment variable. This allows an attacker to perform a timing attack (measuring the time it takes for the comparison to fail) to guess the expected key character by character. Additionally, if the environment variable `INTERNAL_API_KEY` was missing (e.g., evaluated to an empty string or undefined) and the attacker provided a similarly empty header, it could lead to an authentication bypass.
**Learning:** We must not use standard strict equality (`===`) for secrets or tokens. Also, always ensure the environment variable is actually set and valid; do not fall back to an empty string because it can trivially match an empty input.
**Prevention:** Always use `crypto.timingSafeEqual` for sensitive strings. Before comparison, convert the inputs to `Buffer` and verify their byte lengths are equal to prevent `RangeError`. Also, ensure that both the provided key and expected key are truthy/present before performing the comparison.
