## 2025-02-14 - Fix timing attack in internal API key validation
**Vulnerability:** The internal API key check used a strict equality operator (`===`), which is vulnerable to timing attacks that could allow an attacker to guess the API key character by character by measuring the response time.
**Learning:** Hardcoded constant-time comparison methods like `crypto.timingSafeEqual` should always be used for validating secrets like API keys or tokens. However, using `.length` on strings before creating Buffers for `timingSafeEqual` is dangerous because multi-byte characters pass the check but cause unequal buffer sizes, resulting in a length oracle or a TypeError.
**Prevention:** Always compare sensitive strings by converting them to Buffers first (`Buffer.from()`), then verifying their byte lengths match (`buf1.length === buf2.length`) before using `crypto.timingSafeEqual`. Never fallback to empty strings for the API key if one is not provided or the env var is missing.
