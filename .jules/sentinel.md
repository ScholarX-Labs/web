## 2024-11-20 - [API Key Verification] Fix Timing Attack in Strict Equality Comparison
**Vulnerability:** The application was using strict equality (`===`) to verify the `x-internal-key` against `process.env.INTERNAL_API_KEY`. This introduced a timing attack vulnerability, allowing attackers to theoretically deduce the API key by measuring response times. It also allowed an authentication bypass if both the environment variable and header were empty.
**Learning:** Strict equality operators stop comparing characters as soon as a mismatch is found. This variable execution time can leak information about the secret key's characters. When `crypto.timingSafeEqual` is used, it guarantees constant-time comparison but requires comparing Buffers of equal length, avoiding `RangeError`. Empty secrets must also be rejected explicitly.
**Prevention:** Always use `crypto.timingSafeEqual` for sensitive string comparisons like API keys, tokens, or passwords. Convert both inputs to Buffers first, ensure neither is empty, and verify `buf1.length === buf2.length` prior to comparison.
