## 2024-05-18 - [Timing Attack Risk on API Keys]
**Vulnerability:** A strict equality check (`===`) was being used in `src/app/api/admin/storage-check/route.ts` to compare the `x-internal-key` header to the `INTERNAL_API_KEY` environment variable. This is susceptible to timing attacks, where an attacker can determine the key byte by byte based on the response time.
**Learning:** Next.js applications and Edge functions need secure comparisons just like any backend application. `crypto.timingSafeEqual` should always be used to compare keys or secrets. Furthermore, when using `crypto.timingSafeEqual`, strings must be converted to Buffers, and the buffers' byte lengths must be verified to be equal first, to prevent `RangeError` on multi-byte characters and empty string comparisons. Empty string fallback (e.g. `|| ""`) must be avoided since both values being empty would lead to an authentication bypass.
**Prevention:** Use `crypto.timingSafeEqual` with `Buffer.from` and byte length verification for all key/secret comparisons, and avoid empty string fallbacks for keys.
