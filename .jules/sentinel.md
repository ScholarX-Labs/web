## 2024-10-28 - Timing Attack Vulnerability in API Key Verification
**Vulnerability:** A strict equality comparison (`===`) was used in `src/app/api/admin/storage-check/route.ts` to compare the `x-internal-key` header with `process.env.INTERNAL_API_KEY`. This could allow an attacker to determine the API key by measuring the response time, which varies based on how many characters of the provided key match the correct key before the comparison exits.
**Learning:** Comparing sensitive strings like API keys or secrets should never be done with standard string equality operators. Standard operators fail fast, returning false as soon as they encounter a mismatch, which creates a timing side-channel.
**Prevention:** Always use `crypto.timingSafeEqual` for sensitive string comparisons. First convert the input strings to Buffers, verify their byte lengths are identical (`buf1.length === buf2.length`), and then perform the constant-time comparison. Additionally, never use a fallback or empty string for secrets comparison as it can result in bypassing authentication if the environment variable is not set.
