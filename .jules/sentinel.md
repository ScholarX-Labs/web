## 2025-02-28 - [Timing Attack in API Key Validation]
**Vulnerability:** Comparing API keys using strict equality (`===`) in `src/app/api/admin/storage-check/route.ts` exposes the endpoint to timing attacks, allowing attackers to potentially guess the API key character by character by measuring response times.
**Learning:** Security tokens and API keys must be compared using constant-time comparison functions to prevent timing attacks. Additionally, when using Node.js `crypto.timingSafeEqual`, Buffers must be the exact same length or a `RangeError` is thrown, which could lead to an unhandled exception or 500 error if not caught.
**Prevention:** Always use `crypto.timingSafeEqual` for sensitive string comparisons. Check for the existence of both variables first, convert them to `Buffer`s, and verify that `buffer1.length === buffer2.length` before calling `timingSafeEqual`. Do not use empty string fallbacks (e.g. `|| ""`) for both provided and expected keys, as missing environment variables combined with omitting headers could result in an authentication bypass.
