## 2024-08-17 - [Authorization Timing Attack Vulnerability in API Route]
**Vulnerability:** The API route `src/app/api/admin/storage-check/route.ts` used a strict equality operator (`===`) to compare the provided `x-internal-key` against the expected `INTERNAL_API_KEY` from `process.env`. This creates a vulnerability to timing attacks, where an attacker could deduce the secret key character by character by analyzing the response time, as string comparison stops at the first mismatch.
**Learning:** Comparing secrets and authorization tokens should not be done with standard equality operators (`===` or `==`). Additionally, if environment variables or input headers might be empty, relying on fallback empty string values for comparison (`value || ""`) could lead to authentication bypass if both evaluate to empty strings.
**Prevention:** Always use `crypto.timingSafeEqual` (imported from `node:crypto`) to compare sensitive keys or tokens. To ensure this works safely, avoid using empty string fallbacks for both expected and provided keys. Ensure inputs are converted to Buffers, and then verify their byte lengths match (`buf1.length === buf2.length`) before calling `timingSafeEqual` to avoid throwing a `RangeError`.
