## 2025-03-01 - [Timing Attack Prevention in String Comparison]
**Vulnerability:** A standard string equality comparison (`===`) was used for validating an internal API key against environment variables (`request.headers.get("x-internal-key") === process.env.INTERNAL_API_KEY`), opening up the potential for timing attacks.
**Learning:** Comparing sensitive secrets/keys using strict equality is vulnerable to timing attacks as the comparison bails out at the first mismatched character. This leak in timing could allow an attacker to guess the expected string character-by-character. Additionally, missing environment variables and user headers might evaluate to equal conditions if not properly handled (e.g., empty string fallbacks).
**Prevention:** Always use `crypto.timingSafeEqual` for comparing secrets. When utilizing it, convert the inputs to `Buffer` and first verify their byte lengths match (`buf1.length === buf2.length`), preventing a `RangeError` exception when comparing.
