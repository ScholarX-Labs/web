## 2024-05-15 - [Critical] Fixed Timing Attack Vulnerability in API Key Comparison
**Vulnerability:** A strict equality comparison (`===`) was being used to compare the provided `x-internal-key` against the expected `INTERNAL_API_KEY` environment variable in `src/app/api/admin/storage-check/route.ts`. This exposed the application to a timing attack where an attacker could deduce the key character by character by measuring the response time, as strict equality returns early upon the first mismatched character.
**Learning:** When comparing sensitive strings like API keys or secrets, always use `crypto.timingSafeEqual` instead of strict equality (`===`) to prevent timing attacks. Furthermore, always convert the string inputs to Buffers first and verify their byte lengths match (`buf1.length === buf2.length`) before calling `timingSafeEqual`. Never check the `.length` of the raw strings instead, as multi-byte characters will pass the check but cause unequal buffer sizes, leading to a `TypeError` and a potential length oracle vulnerability. Also, explicitly check that the header key and expected environment variable exist before comparing to prevent an authentication bypass if the expected key is missing or undefined.
**Prevention:** Enforce the use of `crypto.timingSafeEqual` with proper buffer length validation for all security-sensitive string comparisons. Avoid defaulting to empty strings for fallback mechanisms as this could accidentally authenticate a missing header if the environment variable is also missing.
