## 2024-05-15 - [Timing Attack Risk in Internal API Key Checks]
**Vulnerability:** Comparing an internal API key from headers with an expected environment variable using strict equality (`===`) exposes the comparison to timing attacks, allowing an attacker to incrementally guess the secret key.
**Learning:** Comparing sensitive strings such as API keys or secrets should always be done using `crypto.timingSafeEqual` in Node.js instead of strict equality. Additionally, the inputs must be converted to `Buffer` and compared by byte length (`buf1.length === buf2.length`) before calling `timingSafeEqual` to avoid `RangeError` exceptions and unhandled application crashes due to unequal length comparisons.
**Prevention:** Use `crypto.timingSafeEqual` from `node:crypto` (especially in Next.js server-side routes to ensure ESM compatibility) and avoid empty string fallbacks (e.g., `|| ""`) to prevent critical authentication bypass if the environment variable is missing and the user omits the header.
