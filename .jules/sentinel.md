## 2025-02-20 - Timing Attack in API Key Comparison
**Vulnerability:** Comparing an expected API key against user input using strict equality (`===`) creates a timing attack vulnerability. An attacker can iteratively guess the API key character by character based on the time it takes the comparison to fail. If `INTERNAL_API_KEY` was missing from the environment, and an empty key was provided, it could also allow an auth bypass.
**Learning:** Security tokens and API keys must be compared using constant-time string comparison methods like `crypto.timingSafeEqual` in Node.js instead of string operators to prevent timing attacks. Empty strings should not be valid fallbacks.
**Prevention:** Always use `crypto.timingSafeEqual` (from `node:crypto`) to compare secrets. Ensure strings are converted to `Buffer` and verified to have matching lengths (`providedBuf.length === expectedBuf.length`) before calling `timingSafeEqual` to avoid `RangeError` exceptions and prevent unhandled application crashes.
