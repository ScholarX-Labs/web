## 2025-02-28 - [Timing Attack via Strict Equality Check on API Key]
**Vulnerability:** The `src/app/api/admin/storage-check/route.ts` used strict equality (`===`) to compare the `x-internal-key` header with `process.env.INTERNAL_API_KEY`. This makes the application vulnerable to timing attacks as string comparison short-circuits on the first mismatched character, leaking the length and correct prefix character by character.
**Learning:** Even internal API keys or secret validations require constant-time comparisons. `crypto.timingSafeEqual` should be used for such checks. Care must be taken to convert the strings to `Buffer` and ensure they are of the same length to prevent `RangeError`. Also, fallback to empty strings should be avoided if variables are missing.
**Prevention:** Always use `crypto.timingSafeEqual(Buffer.from(providedKey), Buffer.from(expectedKey))` for verifying secrets. Ensure `providedKey` and `expectedKey` exist and their buffer lengths are identical (`providedBuffer.length === expectedBuffer.length`) before proceeding to avoid authentication bypass or runtime errors.
