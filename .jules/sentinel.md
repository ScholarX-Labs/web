## 2025-02-14 - Timing Attack on Internal API Key Verification
**Vulnerability:** The internal API key (`x-internal-key`) in `src/app/api/admin/storage-check/route.ts` was being compared to the expected secret (`process.env.INTERNAL_API_KEY`) using strict equality (`===`). This string comparison operator returns `false` as soon as it encounters the first mismatched character, creating an observable timing difference based on how many initial characters match.
**Learning:** Comparing sensitive strings (like API keys, tokens, or passwords) with standard equality operators introduces a timing attack vulnerability. Attackers can perform statistical analysis on response times to brute-force the secret one character at a time.
**Prevention:** Always use `crypto.timingSafeEqual` when comparing sensitive tokens or secrets. Additionally, convert strings to Buffers first and ensure you check that their byte lengths (`buf1.length === buf2.length`) match before running the constant-time comparison. Do not use string length comparisons, as multi-byte characters can cause length mismatches or `RangeError`s during buffer creation.
