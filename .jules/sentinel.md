## 2024-05-24 - [Timing Attack] Constant-time comparison for API keys
**Vulnerability:** The API key verification `request.headers.get("x-internal-key") === process.env.INTERNAL_API_KEY` was using strict string equality (`===`). This allows timing attacks because it evaluates characters sequentially, failing immediately on the first mismatch. Attackers can statistically guess the secret key character by character by measuring the response time.
**Learning:** When comparing sensitive strings like API keys, secrets, or tokens, we must use `crypto.timingSafeEqual`. Before calling `timingSafeEqual`, strings must be converted to `Buffer`s, and their byte lengths must be verified to match (`buf1.length === buf2.length`). Checking the `.length` of the raw strings instead can cause a `TypeError` due to multi-byte characters creating unequal buffer sizes, resulting in a potential length oracle or DoS vulnerability.
**Prevention:** Always verify secrets using constant-time comparisons (`node:crypto.timingSafeEqual`) and explicitly verify buffer byte lengths, never raw string lengths, before comparison. Also, make sure that both keys exist to prevent auth bypass if environment variable is missing.
