## 2024-05-18 - [Timing Attack & Auth Bypass Vulnerability in Internal API Key Comparison]
**Vulnerability:** The internal API key check used strict string equality (`===`) and did not defend against timing attacks. Furthermore, in general security practice, relying on strict equality can be vulnerable to timing attacks, and if an environment variable is omitted alongside the header, using an empty string fallback could lead to a critical authentication bypass.
**Learning:** Security token comparisons must always be done in constant time using `crypto.timingSafeEqual` after converting the inputs to Buffers and strictly verifying their byte lengths match (not just string lengths, as multi-byte characters could trigger a RangeError).
**Prevention:** Never use `===` to compare API keys, session tokens, or cryptographic secrets. Instead, explicitly load both expected and provided values, ensure neither is empty, convert them to `Buffer` objects, verify `length` equivalence, and then use `crypto.timingSafeEqual`.
