## 2025-02-14 - Fix timing attack vulnerability in API key validation
**Vulnerability:** Internal API endpoints used strict equality (`===`) to compare the `x-internal-key` header with the expected `INTERNAL_API_KEY`. This is susceptible to timing attacks, where an attacker measures the time it takes the server to reject an incorrect key to guess the correct key character by character.
**Learning:** Even internal or admin endpoints must use timing-safe comparisons for secrets and API keys. Node.js `crypto.timingSafeEqual` is the appropriate defense, but it requires both inputs to be Buffers of the exact same length.
**Prevention:** Always use `crypto.timingSafeEqual` (or a similar constant-time comparison utility) for secret comparisons. First, check that both the provided and expected keys exist. Then, convert them to `Buffer`s. Next, verify that their byte lengths are equal (`buf1.length === buf2.length`). Only if the lengths match, use `timingSafeEqual`. This prevents `RangeError` exceptions when lengths differ and correctly handles multi-byte characters. Do not use empty string fallbacks (`|| ""`) for both provided and expected keys to avoid bypass when the env var is missing.
