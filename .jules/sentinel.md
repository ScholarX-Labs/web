## 2024-08-10 - Fix timing attack on API key comparison
**Vulnerability:** The application was using strict equality (`===`) to compare the provided `x-internal-key` header with the expected `INTERNAL_API_KEY`. This makes it vulnerable to a timing attack where an attacker can guess the expected key character by character by measuring the response time.
**Learning:** Using `===` for cryptographic/security comparisons is unsafe. `crypto.timingSafeEqual` should be used instead. However, `timingSafeEqual` requires the buffers to be of the exact same length, otherwise it throws a RangeError.
**Prevention:** Always use `crypto.timingSafeEqual` for sensitive string comparisons. Convert strings to Buffers and explicitly verify their byte lengths (`buf1.length === buf2.length`) before calling `timingSafeEqual`. Ensure null/undefined inputs are handled gracefully without defaulting to empty strings that could cause authentication bypass if the environment variable is missing and the user omits the header.
