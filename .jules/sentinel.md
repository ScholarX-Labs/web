## 2024-03-24 - Timing Attack Vulnerability in API Key Comparison
**Vulnerability:** The API key in `x-internal-key` header was being checked against `process.env.INTERNAL_API_KEY` using strict equality (`===`), making it vulnerable to a timing attack where an attacker can progressively guess the correct key by observing response times.
**Learning:** Comparing sensitive variables (like API keys or secrets) with strict equality allows string comparison to short-circuit, causing variations in execution time. In critical checks, using constant-time string comparison is mandatory. Additionally, the inputs should be explicitly checked for existence before conversion, and their lengths must be compared before checking the buffers using `timingSafeEqual`.
**Prevention:** Always use `node:crypto`'s `timingSafeEqual` for comparing secrets, keys, or passwords. Convert both values to `Buffer` and compare their byte lengths (`buf1.length === buf2.length`) before calling `timingSafeEqual`. Never rely on `===` for sensitive strings or fallback to empty strings.
