## 2025-02-14 - Fix Timing Attack in Internal API Validation
**Vulnerability:** The internal API key validation in `src/app/api/admin/storage-check/route.ts` used strict equality (`===`) to compare the provided key with the expected key from environment variables. This creates a timing vulnerability because strict equality checking short-circuits on the first mismatched character. An attacker could potentially extract the internal API key by measuring the response time for various guesses.
**Learning:** Comparing secrets and keys must always be done in constant time to prevent timing attacks. Additionally, when using `crypto.timingSafeEqual`, the buffers must be of identical lengths, otherwise it throws a `TypeError`. Converting strings to buffers before checking their lengths is critical to avoid crashes due to multi-byte characters (length oracle vulnerability).
**Prevention:** Use `crypto.timingSafeEqual()` for comparing secrets. Convert strings to `Buffer` first, then verify the *byte lengths* match (`buf1.length === buf2.length`) before calling the comparison function to prevent unhandled exceptions and crashes.
