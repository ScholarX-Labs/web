## 2024-05-24 - Secure timing-safe string comparison for internal API key
**Vulnerability:** The internal API key was being compared using strict equality (`===`), which is vulnerable to timing attacks. An attacker could potentially guess the `INTERNAL_API_KEY` byte by byte by measuring the time it takes for the comparison to fail. Also it was possible to bypass if the environment variable was missing by sending an empty header, as `"" === undefined` is false, but `undefined === undefined` is true if the header and env var are both undefined. The comparison should use `crypto.timingSafeEqual`.
**Learning:** Always use `crypto.timingSafeEqual` for comparing secrets like API keys or passwords to prevent timing attacks. Ensure the inputs are converted to Buffers and their byte lengths are checked before comparison to prevent `RangeError`. Also, guard against both inputs being empty to prevent bypasses when environment variables are missing.
**Prevention:** Use the `node:crypto` module and `crypto.timingSafeEqual` when comparing sensitive strings. Add checks to ensure both strings are provided and their buffer lengths match before comparing.
