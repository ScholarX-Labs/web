## 2024-06-25 - Prevent Timing Attacks in Internal API Key Validation
**Vulnerability:** Comparing sensitive strings like `x-internal-key` against environment variables using strict equality (`===`) is vulnerable to timing attacks. This allows an attacker to guess the API key character by character by measuring the response time.
**Learning:** Using `crypto.timingSafeEqual` is necessary for comparing secrets. However, there are two common pitfalls: 1) `timingSafeEqual` throws a `RangeError` if the buffers have different lengths, requiring a length check first. 2) Fallback values (e.g. `|| ""`) used to instantiate buffers can lead to an authentication bypass if both the provided key and the expected environment variable are missing (both default to an empty string buffer, making them equal). Furthermore, checking `buf.length` instead of string length is critical because multi-byte characters in the string will cause `Buffer.from(str).length !== str.length`, leading to `RangeError`s even if the strings have the same character count.
**Prevention:** Always use `crypto.timingSafeEqual` when comparing secrets. Ensure both values are present before comparing, convert them to buffers, and compare their `length` (byte length) before calling `timingSafeEqual`. Do not use empty string fallbacks for expected keys.
