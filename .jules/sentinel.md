## 2024-05-31 - [Timing Attack Vulnerability in API Key Comparison]
**Vulnerability:** Comparing sensitive strings like API keys (`INTERNAL_API_KEY`) using strict equality (`===`) allows timing attacks, as strict equality returns early upon the first mismatched character. An attacker can use the timing differences to deduce the expected API key character by character.
**Learning:** It existed because strict equality (`===`) is the standard way to compare strings in JavaScript and is often used mistakenly for secrets. In environments running Next.js or Node.js, `node:crypto`'s `timingSafeEqual` should be utilized for secret comparison to ensure constant time execution regardless of mismatches.
**Prevention:** When comparing sensitive strings (API keys, secrets, passwords, etc.), always use `crypto.timingSafeEqual()`. Furthermore, make sure to handle potential undefined variables (e.g. `process.env` values or missing headers) and first verify that both buffers have the exact same length (`providedBuffer.length === expectedBuffer.length`) before calling `timingSafeEqual` to avoid throwing a `RangeError`. Empty string fallbacks (`|| ""`) should be avoided for security logic.
