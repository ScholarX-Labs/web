## 2024-03-24 - [Fix timing attack in API Key Comparison]
**Vulnerability:** Comparing sensitive strings like API keys using strict equality (`===`) creates a timing attack vulnerability. An attacker can infer the value of the expected key character by character by measuring the response time, since a string comparison terminates early on the first mismatched character.
**Learning:** We must use `crypto.timingSafeEqual` for comparing secrets. Also, we need to convert strings to Buffers first and ensure we're comparing matching byte lengths, rather than string lengths, because `timingSafeEqual` throws a `RangeError` if the buffers have different lengths.
**Prevention:** When comparing sensitive strings like API keys or secrets, always use `crypto.timingSafeEqual` instead of strict equality (`===`) to prevent timing attacks. Convert the inputs to Buffers first and verify their byte lengths match (`buf1.length === buf2.length`) to prevent a `RangeError`. Also, verify empty string fallbacks (e.g. `|| ""`) do not create an authentication bypass if the environment variable is missing and the user omits the header.
