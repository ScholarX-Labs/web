## 2025-01-20 - [CRITICAL] Prevent timing attack and auth bypass on internal API key check
**Vulnerability:** A timing attack was possible because of strict equality string comparison (`===`) being used for comparing secrets like `request.headers.get("x-internal-key") === process.env.INTERNAL_API_KEY`. Additionally, if both the header and environment variable were empty strings/undefined, the check would pass, leading to authentication bypass.
**Learning:** Comparing secrets using normal equality (`===`) is vulnerable to timing attacks since the comparison stops early if characters don't match, allowing an attacker to guess the secret character by character. Furthermore, empty string fallbacks for both inputs can lead to complete authentication bypass if the environment variable is inadvertently missing.
**Prevention:** Always use `crypto.timingSafeEqual(buf1, buf2)` to compare secrets. Ensure the inputs are converted to Buffers, and only call `timingSafeEqual` if their byte lengths match (`buf1.length === buf2.length`). Avoid empty string fallbacks for both the expected key and provided key without also checking if they are non-empty.
