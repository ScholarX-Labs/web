## 2024-05-24 - [Timing Attack in API Key Validation]
**Vulnerability:** A strict equality operator (`===`) was used to validate an internal API key against a stored environment variable. This allows attackers to perform a timing attack by measuring the response time, which can leak information about the length and characters of the correct key since the comparison exits early on a mismatch.
**Learning:** Security-sensitive string comparisons (like API keys, passwords, or HMAC signatures) should never use simple equality operators (`===` or `==`). Even subtle time differences can be weaponized. Also, fallback behavior must be carefully considered so that if both values are missing or empty, it doesn't default to a valid state.
**Prevention:** Always use `crypto.timingSafeEqual(bufferA, bufferB)` for sensitive string comparisons. First convert both the provided and expected strings into `Buffer`s. Ensure that you check `bufferA.length === bufferB.length` before calling `timingSafeEqual` to avoid a `RangeError`. Also, verify that both the provided key and expected key are truthy to avoid edge cases.
