## 2024-05-18 - API Key Timing Attack Vulnerability
**Vulnerability:** Internal API key validation used strict equality (`===`) (`request.headers.get("x-internal-key") === process.env.INTERNAL_API_KEY`). This allowed for a potential timing attack, and more critically, could lead to a complete authentication bypass if `process.env.INTERNAL_API_KEY` was undefined and the user omitted the header (or if fallbacks were improperly used like `|| ""`).
**Learning:** Comparing sensitive strings like API keys or secrets should always use `crypto.timingSafeEqual` instead of strict equality to prevent timing attacks. It's crucial to check that both strings are truthy (not undefined/null) before converting to buffers.
**Prevention:** Always use `crypto.timingSafeEqual` for comparing secrets. Convert inputs to Buffers first and verify their byte lengths match (`buf1.length === buf2.length`), instead of string lengths, to prevent a `RangeError` with multi-byte characters. Never use empty string fallbacks (`|| ""`) for both the provided and expected keys, as this creates a critical authentication bypass if the environment variable is missing and the header is omitted.
