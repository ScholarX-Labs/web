## 2024-05-18 - Timing Attack Vulnerability in API Key Validation
**Vulnerability:** The internal API key (`x-internal-key`) validation in `src/app/api/admin/storage-check/route.ts` used strict equality (`===`) to compare the provided key with the expected key from the environment. This exposed a timing attack vulnerability, where an attacker could theoretically determine the length and value of the expected key by measuring the response time of the API.
**Learning:** This vulnerability existed because the standard JavaScript equality operators (like `===`) fail-fast as soon as they encounter a mismatching character. This causes a predictable difference in execution time based on the number of matching characters, which can be measured remotely over a large enough sample size.
**Prevention:** Always use a constant-time comparison function, such as `crypto.timingSafeEqual`, when comparing sensitive strings like API keys, secrets, or passwords. When doing so, ensure that both inputs are converted to Buffers and that their lengths are explicitly checked for equality (`buf1.length === buf2.length`) before calling the function to avoid `RangeError` exceptions with multi-byte characters. Do not use empty string fallbacks (e.g. `providedKey || ""`) as this could lead to bypasses if both variables evaluate to empty strings.
