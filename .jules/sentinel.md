## 2024-05-18 - [Authentication Bypass & Timing Attacks in String Comparisons]
**Vulnerability:** Comparing sensitive authentication tokens like `INTERNAL_API_KEY` using strict equality (`===`) is vulnerable to timing attacks.
**Learning:** We need to use `crypto.timingSafeEqual`. However, when using `crypto.timingSafeEqual`, the comparison requires standardizing input lengths (or verifying they match), otherwise a `TypeError` (e.g. `Input buffers must have the same length`) is thrown which acts as a length oracle. When verifying secrets, ensure you aren't checking the byte lengths of `string` natively because multibyte characters can cause length mismatches despite having identical string length, leading to length oracles as well. Also, ensure neither string can be empty or default, as that leads to bypasses if the env var is missing.
**Prevention:** Convert the authentication strings to `Buffer`s, securely verify their lengths match (`buf1.length === buf2.length`), and confirm both expected and actual keys exist prior to executing `crypto.timingSafeEqual(buf1, buf2)`.
