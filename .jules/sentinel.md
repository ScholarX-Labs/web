## 2025-03-09 - [Internal API Key Timing Attack Vulnerability]
**Vulnerability:** A simple string equality operator (`===`) was used to verify the `x-internal-key` against `process.env.INTERNAL_API_KEY` in `src/app/api/admin/storage-check/route.ts`. This exposed the authentication endpoint to timing attacks, where an attacker could theoretically guess the API key by analyzing response times for various character inputs.
**Learning:** Checking secure values like API keys and passwords requires constant-time comparison to prevent information leakage through response timing. Using native string comparisons exits early upon the first mismatching character, which is exactly what creates the vulnerability.
**Prevention:** Always use `crypto.timingSafeEqual` for comparing sensitive keys or hashes in restricted internal routes. Before passing to `timingSafeEqual`, verify both sides are truthy, explicitly check the lengths to match, and wrap the strings as Buffers (`Buffer.from()`). Avoid using empty string fallbacks (e.g., `|| ""`) to avoid the auth bypass case if an environment variable is unexpectedly undefined.
