## 2026-06-26 - [Timing Attack Risk on Internal API Key Comparison]
**Vulnerability:** The internal API endpoint (`src/app/api/admin/storage-check/route.ts`) was using strict equality (`===`) to compare the provided `x-internal-key` header with the expected `INTERNAL_API_KEY` from the environment. This exposed the endpoint to potential timing attacks, where an attacker could theoretically infer the secret key character-by-character by measuring the time the comparison takes (since strict equality returns early as soon as a mismatch is found).
**Learning:** Comparing sensitive secrets or API keys using standard string comparison operators allows for timing attacks. Furthermore, using empty strings as fallbacks during comparison could inadvertently cause an authentication bypass if both sides evaluate to an empty string.
**Prevention:** Always use `crypto.timingSafeEqual` for comparing secrets or API keys. Ensure that inputs are converted to `Buffer`s, their byte lengths are matched first (`buf1.length === buf2.length`), and avoid using empty string fallbacks for both provided and expected keys.
