## 2025-02-18 - [Fix Timing Attack Vulnerability in Internal API Authentication]
**Vulnerability:** The internal API endpoint (`/api/admin/storage-check`) was comparing the sensitive `x-internal-key` header to `process.env.INTERNAL_API_KEY` using strict equality (`===`). This allows timing attacks, where an attacker can theoretically determine the correct key by measuring the time it takes for the comparison to fail.
**Learning:** Using standard string comparison operators (`===`) on security-sensitive values (like API keys, secrets, or tokens) exposes the application to timing attacks because standard comparison exits early as soon as a mismatch is found.
**Prevention:** Always use `crypto.timingSafeEqual` when comparing security-sensitive strings. Convert the strings to Buffers first, and ensure the buffers are of equal length before comparing them (`buf1.length === buf2.length`). Additionally, always verify that both the provided key and expected key are defined and not empty strings, as comparing empty buffers or allowing fallback empty values can lead to bypasses.
