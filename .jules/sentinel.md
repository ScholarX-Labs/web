## 2024-05-18 - [Timing Attack Risk on Internal API Key Verification]
**Vulnerability:** The internal API key verification in `src/app/api/admin/storage-check/route.ts` used strict equality (`===`) to compare the provided key with the expected key, which is susceptible to timing attacks. This could potentially allow an attacker to guess the API key character by character by measuring the response time.
**Learning:** Security-sensitive string comparisons like API keys, secrets, or hashes must always use constant-time comparison algorithms (e.g., `crypto.timingSafeEqual`) to prevent timing side-channel attacks. Furthermore, when using `crypto.timingSafeEqual`, verifying that both values are valid non-empty strings before converting them to buffers prevents authentication bypasses if the expected environment variable is undefined or an empty string, and the provided key is also empty. Also, it is critical to compare `Buffer` byte lengths (`buf.length`), rather than string characters (`string.length`), before comparing buffers, to handle multi-byte characters and prevent `RangeError`.
**Prevention:** In the future, always implement robust, constant-time validation for API keys and secrets, use Buffer length checks before comparison, and enforce that both strings are valid and expected environment variables are actually configured.
