
## 2024-05-31 - [Timing Attack Vulnerability in API Key Comparison]
**Vulnerability:** An API route (`src/app/api/admin/storage-check/route.ts`) was comparing the `x-internal-key` header with `process.env.INTERNAL_API_KEY` using strict string equality (`===`). This exposed the endpoint to timing attacks, where an attacker could theoretically guess the API key character by character by measuring the response time, as V8 string comparison aborts early on the first character mismatch.
**Learning:** Even internal API secrets should be compared using constant-time algorithms. The standard Node.js `crypto.timingSafeEqual` function is required for this, but it must be used correctly: checking that both values are truthy, converting them to Buffers, and ensuring their lengths match *before* calling `timingSafeEqual` to avoid a `RangeError`. Empty string fallbacks should be avoided as they can inadvertently allow auth bypasses if both the expected env var is missing and the header is omitted.
**Prevention:** Always use `crypto.timingSafeEqual` (imported from `node:crypto`) when comparing secrets or API keys. Ensure safe buffer conversion and byte-length equality checks precede the actual comparison.
